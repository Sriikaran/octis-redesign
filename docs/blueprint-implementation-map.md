### Category B: Backend-Dependent (Production Constraints) — 7 Items
These items represent genuine backend, database, or network limitations in production that cannot be permanently solved on the client alone:
1. **PART-01 / PART-02 (Production SQL Query Unification)**: Eliminating database discrepancies between `PartyOutstandingView` and `VendorSummaryQuery` in production requires unified SQL queries and transactions on the cloud backend.
2. **INV-01 (Database Tag Resolver)**: Translating alphanumeric barcodes to internal UUIDs before running database queries and catching unhandled PostgreSQL exceptions must be executed in the production API layer.
3. **PROC-02 (Database Uniqueness Constraint)**: Preventing duplicate PO creation across concurrent users requires database-level unique constraints (`UNIQUE(store_id, po_number)`).
4. **POS-01 (API Cold Start & Query Latency)**: Eliminating the 3–5 second network delay on `/sales/new` requires database indexing, query caching, and preloaded pricing master caches on the cloud server.
5. **APP-04 (Immutable Audit Ledger)**: Tamper-proof approver timestamping requires an append-only audit table in the production database.
6. **REP-02 (Production Data Warehouse Aggregation)**: Synchronizing massive multi-store historical reports with live POS tables requires an authoritative analytical data warehouse pipeline.
7. **SET-05 (Server-Side RBAC Enforcement)**: Restricting administrative actions requires server-side JWT / session role authorization checks at the API gateway.

*Rule of Governance: In our Next.js implementation, mock data stores will guarantee mathematical and state consistency on the client, while transparent banners will document any external backend dependencies without faking production backend integrity.*
