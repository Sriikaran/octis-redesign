## 3. Strict Classification: Frontend-Only vs Backend-Dependent Work

### Category B: Backend-Dependent (Production Systems & Real Data Constraints)
These items represent genuine backend, database, or network limitations that cannot be permanently solved in a static frontend clone without real backend code:
1. **PART-01 / PART-02 (Production SQL Engine)**: Eliminating database discrepancies between `PartyOutstandingView` and `VendorSummaryQuery` requires modifying the server-side SQL views and transactions in the production Octis backend.
2. **INV-01 (Database Layer)**: Safely casting alphanumeric tags to UUIDs and catching unhandled PostgreSQL exceptions must be executed in the production backend ORM/API handler.
3. **PROC-02 (Database Constraints)**: Preventing duplicate PO creation across concurrent users requires database-level unique constraints (`UNIQUE(store_id, po_number)`).
4. **POS-01 (API Latency)**: Reducing the initial 3–5 second network delay on `/sales/new` requires database indexing, query caching, and preloaded pricing master caches on the cloud server.

*Rule of Governance: In our Next.js implementation, mock data stores will guarantee mathematical and state consistency on the client, while transparent banners will document any external backend dependencies without faking production backend integrity.*
